# P0 pipeline repair plan

Reviewed 2026-07-19. This plan is for implementation after the lineage review. It does not authorize retraining, changes to Strategy A thresholds, a fixed 13:00 rule, production max-lock logic, or Kelly changes.

## Principles

- v1 and v2 remain independent adapters.
- v2 is the preferred Model 2A implementation.
- No automatic `wind_highland_*` ↔ `wind_offshore_highland_*` translation.
- Do not change v2 wind calculation unless a v2-specific test proves a mismatch with the v2 training pipeline.
- Repairs must fail closed on ambiguous artifact/spec/version/schema state.
- Use shadow/replay evidence before changing model or strategy policy.

## Explicitly deferred

- Retraining Model 2A v1 or v2.
- Changing A/B/C feature sets or morning model policy.
- Strategy edge thresholds, entry windows, fixed 13:00 cutoff, max-lock production logic, and Kelly fractions.
- Applying v2 interval-calibration factors live.
- Any renaming of v2 wind fields.

## Test plan

1. **v1 artifact ↔ v1 spec:** load v1 YAML, v1 feature list, all five quantile boosters, classifier, and threshold; assert model version and exact ordered feature names.
2. **v2 artifact ↔ v2 spec:** repeat for v2; assert `wind_offshore_highland_mean/max` and no required v1 highland fields.
3. **Runtime component ↔ intended version:** app keys, explicit realtime adapters, monitoring utilities, scheduler-selected model keys, replay metadata, and research scripts must identify v1/v2 separately.
4. **Exact names and order:** compare JSON feature list with every booster’s embedded feature names; reject duplicate, missing, extra, or reordered names.
5. **No silent cross-version fallback:** deliberately point v1 spec at v2 directory and v2 spec at v1 directory; both must fail before scoring. Missing feature fields must fail closed.
6. **Missing/stale weather status and adapter flags:** exercise fresh, empty, cached, stale, and anomalous wind/forecast inputs; assert truthful timestamp/age/missing/stale/fallback/source fields, intended quality-flag bit values, and no adapter `TypeError` or fabricated freshness.
7. **CLOB execution:** test depth-walk buy VWAP, sell VWAP, per-level fees, partial fills, stale quote rejection, token/schema validation, and no-depth fail-closed behavior.
8. **2026-07-19 replay:** reproduce the stored model probabilities and the known 30.6°C final bucket; label stored versus regenerated values and do not mix v1/v2 lineage in one result.
9. **No trained-artifact changes:** hash or compare the model directories before/after implementation; `git diff -- models/` must remain empty for repair-only changes.
10. **No policy changes:** assert strategy thresholds, entry windows, max-lock setting, and Kelly fractions are unchanged in repair-only tests.

## Rollback and release gates

Implement each order as a separately reviewable change. Model artifacts and feature-store data are read-only release inputs. A failed schema, source-status, CLOB, or replay test blocks promotion of that task. Rollback means disabling the new adapter/execution/status consumer feature flag or reverting that isolated change; it does not mean renaming features, editing weights, deleting runtime data, or silently falling back to another model version.
